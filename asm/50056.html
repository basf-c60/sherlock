C388: PLOT-CHAR: draw one character glyph at HL, shifted by C
Computes the source glyph address as A*8 + $3C00 - which is exactly the real 128K/48K ROM's own character-bitmap layout (space, code 32, sits at $3D00 = $3C00 + 32*8), confirming A is a plain ASCII code here, not some internal token.
For each of the glyph's 8 pixel rows, shifts the byte right by C bits (carrying into the next screen byte, via the 'or c' merge at C3B0/C3CD) so that text can be printed at any pixel column, not just 8-pixel-aligned ones - this is why the routine is more involved than a plain 1:1 glyph copy.
Input
A The character
HL The screen address
C The pixel shift
Output
The glyph drawn; all registers kept
