CC78: Run one step of the current actor's plan script
Each actor (the 8-byte records at 9860: +0 id, +1/+2 script position, +3/+4/+5 saved plan registers) runs a script in a small language. Each instruction starts with one byte: the low nibble is the opcode and the high nibble holds flags. Bit 7: a 2-byte success address follows the operands. Bit 4: a 2-byte failure address follows (after the success address, if both).
Opcodes (lengths from CF03): 1 DO verb (2 bytes); 2 DO verb dobj iobj (4); 3 RUN record (3); 4 ASK person TO verb dobj iobj (5): an order to another character, queued on the list at 9FEE and announced with 682A; 5 SAY TO person message (4), via 6830; 6 PRINT message (3); 7 RUN record dobj iobj (5); 8 SIGNAL actor (2) and 9 AWAIT actor (2): one actor leaves a token on the 9FE7 list for another, which AWAIT consumes; A RETURN FAIL and B RETURN OK (1 each): leave a sub-script; D (2) and F (1) PASS: spend a minute doing nothing; E GOTO address (3). C is not used: CD08 is JR Z,CD08, a jump to itself with Z set, which would hang the game.
DO runs a command for the actor exactly as if it had been typed, through C4D1: the verb's own default record, the object's own action list, the requirement codes and the pre-check all apply. Verbs 128-140 exist only for scripts and are looked up in the table at 9FAB. RUN skips the verb and runs one action record directly (C591). Argument bytes $F5-$FF are not objects: $FA is the plan's verb (9FD6), $FB the actor itself, $FC and $FD the plan's indirect and direct objects (9FD8, 9FD7), $FE a number and $FF nothing (CEDE).
Success (CE8F) moves to the success address or the next instruction and returns to the main loop, which runs the next step at once if the action took no time and otherwise ends the actor's turn for as many minutes as it took. Failure (CEB8) moves to the failure address or the next instruction and tries again at once, up to ten times in one turn (CC0B); if the failure address is the instruction itself, the actor simply waits there. So 'DO verb 136 / 23 [fail -> itself]' means 'wait here until 11pm'.
A RUN or DO that reaches a checks-only action record (flags bit 7) calls a sub-script: C9A7 saves a call frame (CF80: actor, return position, objects, plan verb) on the list at 9FE9 and points the actor at the script after the record's header. RETURN OK or RETURN FAIL (CFCF) drops the frame and makes the calling instruction succeed or fail.
This routine fetches the actor's script position (+1/+2 of its record), skips spent one-shot bytes, and dispatches on the opcode. CCA7-CCC6 is a separate path for an actor who has been given an order (ASK) this turn ($CC0D, set by CC37 from B91F): the order is carried out first, through B936.
How it works:
1. Set up the actor (CC5A) and load its plan registers (D008). Take its script position from its record.
2. If ten steps have failed this turn, give up until next turn (CD8B). Skip any zero bytes (spent one-shot instructions).
3. The opcode is the low nibble of the first byte. Codes of 10 and up are control flow (CCF3); the others are actions. If an order was given this turn, turn it into a command (B936) and carry it out first.
4. Run the instruction. It succeeds (CE8F), moving to its success address, or fails (CEB8), moving to its failure address, and a one-shot instruction is erased (CF43).
