C41F: GET-KEY: has the player pressed a key?
Saves IY/IX/HL/DE/BC, points IY at the standard system-variable area ($5C3A), then does EI; HALT; DI - i.e. waits for exactly one interrupt, which is where a real Spectrum's ROM would normally have scanned the keyboard into FLAGS/LAST-K.
Checks FLAGS bit 5 ("a new key is waiting"); if not, returns A=0.
Called from three places, all real CALL instructions: $A080 (non-blocking poll during boot), $A53B, and $C416 (the wait-for-a-key loop at C415).
How it works:
1. Save the registers and point IY at the system variables.
2. Allow one interrupt (EI, HALT) so the keyboard is scanned.
3. If no new key is flagged, return 0. Otherwise take the key from $5C08, turn the ROM's editing codes into backspace and '[', and put it in capitals.
4. Set bit 7 to say a key was pressed.
Output
A The key with bit 7 set, or 0 if none
All other registers kept
C41F PUSH IY Save every register this routine touches
C421 PUSH IX Save IX, HL, DE, BC
C423 PUSH HL Save HL on the stack
C424 PUSH DE Save DE on the stack
C425 PUSH BC Save BC on the stack

C434 XOR A No: return with A=0

C43C LD A,($5C08) A = the key, already decoded to ASCII by the ROM
C43F CP $5F Is it the ROM's DELETE-key code?

C443 LD A,$18 ...remap it to a plain backspace
C445 CP $0C Is it this other ROM editing code?

C449 LD A,$08 ...remap it too
C44B CP $0B Is it this third ROM editing code?
