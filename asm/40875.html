9FAB: Verbs 128-140: the verbs only plan scripts use
A DO instruction in a plan script with a verb number of 128 or more comes here instead of to the parser's verb table: C4D1 sends verbs with bit 7 set to C583, which takes the record for verb 128+n from entry n. The player can never type these. Records with flags bit 7 set are sub-scripts.
Found the hard way: once the verb default table at 9F38 was marked as data, the automatic split's code block starting at 9FC3 - in the middle of this table - collided with the action record at 9FC5, and the round trip failed until this table was marked as data too.
9FAB DEFW $E497 Verb 128: E497 - PUT: move the direct object into room (indirect object); room 0 is off stage
9FAD DEFW $E5D8 Verb 129: E5D8 - IS WITH: are the direct and indirect objects in the same room?
9FAF DEFW $E5FD Verb 130: E5FD - IS HERE: is the direct object with the actor (C863)?
9FB1 DEFW $E5AD Verb 131: E5AD - IS IN: is the direct object in room (indirect object)?
9FB3 DEFW $F210 Verb 132: F210 - LOCK: set bit 0 (locked) of the direct object's +5 flags
9FB5 DEFW $F203 Verb 133: F203 - UNLOCK: clear bit 0 (locked) of the direct object's +5 flags
9FB7 DEFW $EB8B Verb 134: EB8B - sub-script: FOLLOW the direct object until in room (indirect object)
9FB9 DEFW $ED28 Verb 135: ED28 - sub-script: OPEN, GO THROUGH and CLOSE a door
