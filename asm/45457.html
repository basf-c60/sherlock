B191: Match the typed command against the verb patterns
Clears the object ids ($A034, $A035), then asks B39D to match the parsed words against the verb patterns at 8259. On a match, IX points at the matching 8-byte pattern; the loop at B1BA turns that into the verb number by counting 8-byte steps back to 8259, and stores it in $A033.
The line comments were written from reading the code and the descriptions of the routines it calls; the counters ($B170 direct, $B171 indirect) and the saves at $B184/B185 are clear, but which message each failure path finally prints was not run for every path.
How it works:
1. Set both object numbers ($A034, $A035) to $FF and clear the 17 bytes of the parser's work space at B16D.
2. Match the parsed words against the verb patterns (B39D). If none matches, return Z with HL = B84C, the routine that says the verb is not known.
3. Turn the matching record's address into a verb number (records are 8 bytes from 8259, counting from 1) and keep it in $A033, with the record's address at $B18E.
4. For verb 46 (TALK TO) swap the six bytes between A002 and the object slot, as bit 0 of B16D says.
5. Copy the typed objects into the two slots in the verb's order (B405), and count the candidates for each (B308, B32D).
6. Ask which one is meant (B6AE) if there are too many, or none if there are too few; otherwise choose the direct and indirect objects and return NZ.
