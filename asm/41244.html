A11C: Allocate A + 3 bytes from the free list, cleared
Walks the free blocks from 9FE3 (each starts with its size and a link) and takes the smallest that is big enough - best fit. If what would be left is under 4 bytes the whole block is unlinked, otherwise it is split. The block is zeroed, its size stored before it, and IX returned on it with NZ. No block big enough: C1D8 (out of memory). Word lists, remarks and orders are built in these blocks; A1AF frees them.
How it works:
1. C = the number of bytes wanted + 3 (the size field and the link).
2. Walk the free list from 9FE3. Each free block begins with its size and a link. Blocks that are too small are passed over.
3. Of those that are big enough, remember the smallest (best fit), and the link that points to it.
4. If none fits, go to the out-of-memory routine at C1D8.
5. If the chosen block would leave 4 bytes or more, split it: the free block keeps the front part and the end is handed out. Otherwise the whole block is taken and unhooked from the free list.
6. Store the size before the block, clear its data and return NZ with IX at the block.
Input
A The number of data bytes wanted (3 more are used for the header)
Output
IX The cleared block
F NZ on success; out of memory ends in $C1D8
