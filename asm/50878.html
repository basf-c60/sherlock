C6BE: Check the indirect object against the action record's requirement
As C628, for the indirect object and the low nibble of byte 1 ($A010). C6B8 sets $A021 = 1 (the indirect object is being checked); C654 sets it to 0.
How it works:
1. Take the indirect object's requirement code from the low nibble of byte 1 of the record. Zero means no requirement: pass.
2. Codes 5 and 6 want a number (the parser's number marker is $FE, the value in $A031): code 5 needs bit 7 of the value clear, code 6 needs it set.
3. Codes 1 and 2 want a room whose record has bit 7 of its first byte set; codes 1 and 3 also want the room to be next door to the actor (D471).
4. Codes 7 to 15 are handed to C7A6 along with the object's id, which is also stored at $CB7A so that a refusal can name it.
5. A failure there sets $A021 and refuses.
Input
IY The action record
Output
F NZ if the indirect object is acceptable, Z if refused (the refusal is printed by $DC15)
